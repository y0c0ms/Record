How it works

Four steps, no instrumentation required

Record works at the browser automation layer, so there is nothing to add to the app under test. It works on any site you can reach, including the local demo on this page.

1

Hit record

A real Edge window opens. A small recorder script is injected into every page; the app itself is untouched.

2

Use the browser

Click, type, select, navigate. Each action is captured with a locator chosen by Playwright's priority rules.

3

Hit stop

The step list is final. Each step has a plain-English title, the locator used, and a JSON form.

4

Replay or export

Replay runs the steps one at a time with per-step screenshots, or export a spec for npx playwright test.

What already exists — and where Record fits

Why not just codegen?

Because a code file is not a review artifact. The step list is what a QA or business reviewer can read and sign off before anything runs.

Why Edge specifically?

Enterprise users live in Edge, behind corporate proxies and policies. Driving the installed browser means zero download and real-world fidelity.

What this POC proves

The whole loop — capture, discrete steps, replay, export — is implementable in a small codebase with no proprietary engine.

FAQ

Straight answers

Does it need a browser download?

No. Playwright launches your installed Microsoft Edge through channel: 'msedge'. If Edge is missing, start the sidecar and it will say so.

Are recorded flows stable?

Locators follow Playwright's priority: data-testid, then role plus accessible name, then label, then text, then a CSS path. Adding test ids to the app under test makes flows near-unbreakable.

What happens to secrets?

Values typed into password fields are masked in the step list and in the exported spec.

Where do recordings live?

On disk, as JSON per session under data/sessions, with generated specs under generated/. Nothing is uploaded.
